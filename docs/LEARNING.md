# Founder and maintainer competence track

The engineer is not required to type all code manually, but must understand and maintain the parts they own. AIEI ties education to actual review work instead of imposing a separate abstract course.

1. **TRACE** — explain HTTP route, verified identity, authorization, service, persistence, returned error and current source files.
2. **REPRODUCE** — run a deterministic failing test, explain why it fails, make a bounded repair and rerun.
3. **CHALLENGE** — independently identify a missing negative case, then prove or disprove the suspected defect.
4. **OPERATE** — investigate a synthetic incident, identify deployed artifact, test backup restore and explain rollback limits.
5. **REVIEW** — approve, reject or escalate a scoped change using observed evidence and a human's own explanation.

Five-question teach-back for substantive reviews:

- What actual user problem does this solve?
- Where does the request and its private data travel?
- What invariant must remain true and what changed?
- What is the strongest credible abuse/failure case and how is it tested?
- Which checks were actually observed at the correct version, what remains unknown and how is recovery performed?

A model-authored response is a draft, not proof that the maintainer understands. Future employees advance through live demonstrations, least-privilege access and competence, not token count, time served or autogenerated quiz scores. Regulated work may require independent professional qualifications.
